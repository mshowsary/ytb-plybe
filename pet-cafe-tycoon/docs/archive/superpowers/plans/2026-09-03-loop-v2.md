# Pet Café Tycoon — Loop v2 Implementation Plan (2026-09-03)

**Spec (binding):** `docs/superpowers/specs/2026-09-03-loop-v2-design.md`. Three tasks, sequential. Process per the user's instruction: no new unit tests beyond what a task needs to compile its contract; the existing suite (`npm test`) must stay green because it is free; each task ends with a cold-start play strip (`node tools/strip.js --cold`) that the controller inspects; no per-task review agents; one final whole-branch review before deploy. Implementers run every long command in the foreground with a timeout and never wait on background monitors. If an assertion or behaviour looks impossible after 3 honest attempts, stop and report the evidence.

## Global constraints (unchanged)
Build guard rules; no `Math.random` in `src/sim`; `src/sim/nav.js`, `src/sim/mover.js` and `test/nav-fullhouse.test.js` stay untouched except where a task says how the test's stocking loop adapts to displays; draw-call budget 200 at full house; palette; chest carry.

## Task 1 — Dedicated displays + explicit interaction (M)

**Data (`data/area1.js`)** — replace the three counters with displays and add the return crate; keep positions on the counter row:
- `dispCookie` type `display`, product `cookie`, (2.0, −2.0), cap 8; `dispCupcake` (5.0, −2.0) cupcake, builtBy `z_oven2`; `barCoffee` (−1.0, −2.0) coffee, builtBy `z_coffee`; `barSmoothie` (8.0, −2.0) smoothie, builtBy `z_blender`. Footprint 2.4×1.0, queue 5 slots south as now.
- `pantry1` (was storage1) (−2.5, −5.2), builtBy `z_coffee`; `return1` type `return` (−4.0, −5.2), 1.0×1.0, always active, front south.
- Kiosk exists from the start (no zone); hire desk stays a zone.
- Zone chain (price, adds): `z_seats1` (65, seat1–2) → `z_oven2` (120, oven2 + dispCupcake) → `z_register2` (180) → `z_hire` (240) → `z_coffee` (360, coffee1 + barCoffee + pantry1) → `z_garden` (450, bush1–3) → `z_seats2` (600, seat3–6) → `z_bowl` (700, bowl1) → `z_blender` (800, blender1 + barSmoothie). No gate zone; `gate1` removed from data.

**Sim (`world.js`, `customers.js`, `staff.js`, `economy.js`, `carry.js`)**
- Display station: `{ type: 'display', product, stock: 0, capacity: 8 }`; `putOnDisplay(w, id, key, n) → placed` (rejects other products), `takeFromDisplay(w, id) → key|null`. Remove `putOnCounter/takeFromCounter/takeProduct` and `w.counters`; add `w.displays`. `DISPLAY_CAP_LEVELS` → star levels later (Task 3); for now cap 8.
- Customers: wish product → queue at the display of that product (if inactive or empty: settle-for after 6 s to any stocked display, as now). Register flow unchanged. Full-house test: its stocking loop becomes "fill every active display to capacity with its product" (the only edit allowed in that file, marked).
- Carry: single product type — `G.carryKey` (`null` when empty); taking a different product is refused. Sacks/fruit unchanged. `returnAll(carry, owner)` empties everything at the return crate.
- Runner: `s.assign = displayId | null`; an assigned runner services only that display from the matching source (oven/coffee/blender); unassigned runners behave as now but never take a product a display cannot hold. Hire panel row gets a display picker (Task 2 renders it; Task 1 stores the field and lets `stepStaff` respect it).
- `jobs.js`: `emptyDisplayWithWaiting` per display; `next` and `jobTarget` use displays.

**Interaction (`src/systems/stations.js`, `src/systems/customers.js`)**
- Explicit pickup: a station acts only when the owner is inside its front zone AND `speed < 0.6` for ≥ 0.25 s (`dwell` accumulator per station, reset on leaving or moving faster) AND facing it (dot(owner facing, station − owner) > 0.3). Same rule for drops and sack/fruit actions. While moving through a zone nothing happens.
- Pantry: on dwell, open a two-button popup (`sheets.open('pantry', {beans, kibble}, {pick})`) — Task 2 styles it; Task 1 adds the plain kind. Picking hands the sack; the popup closes.
- Return crate: on dwell with anything in hand → `returnAll`, toast "Returned".
- "Hands full · cookies" tag under the crowd pill while `carryKey` is set and the player dwells at a station of another product.
- Remove every proximity auto-open for kiosk/hire (Task 2 adds the floating button; until then the kiosk opens on dwell + a tap on the HUD "Upgrades" button — add a temporary HUD button).

**Bot (`botDecide.js`, `tools/bot.js`)** — restock per display by wish demand; obey the single-product carry; use the return crate when wedged; runner assignment on hire (first runner → cookie display).

**Strip** — add `--cold` to `tools/strip.js`: start with 0 coins, no builds, 3 minutes, 12 frames; the controller judges from it.

**Done when:** `npm test` green (incl. full house), `npm run bot` completes all zones, `node tools/strip.js --cold` produced, `npm run build` `postbuild OK`. Commit `feat: dedicated displays, explicit interaction, return crate, pantry popup`.

## Task 3 — Rhythm, stars, economy (M)

- Day clock (`src/sim/day.js`): `G.day`, `G.dayT`, phases morning 60 / rush 90 / afternoon 60 / closing 30; `phaseSpawnMult` 0.7/2.0/1.0/0; `tipMult` 1.0/1.5/1.0; rush adds +4 to the customer cap; weekend (day % 7 === 6 or 0): rush spawn ×1.5, pets ×2 (treat wish probability 1.0), tips ×1.25; holiday (day % 7 === 0): `holidayCupcake` wish 30 % at 2× price from the cupcake display; banners via `hud.banner(text)`; closing: spawns stop, leaving customers finish, a summary card (`sheets.open('summary', …)`) with earnings, served, lost, stars, tomorrow's goal + reward, next unlock preview; the next day starts on CONTINUE.
- Goals: `G.goal = { kind: 'serve'|'lose'|'earn', target, reward }` chosen per day from the spec table; evaluated at closing.
- Stars: `G.stars[stationId] 1..3`; Machines tab rows per station: star 2 (+50 % speed or capacity), star 3 (second recipe: Oven A brownie, Coffee latte — new products with icons, prices ×1.6, sold from the same display type); tapping a chalkboard opens the panel on that row. Café level = total stars; every 5 → decoration set (awning colour change) and +1 base cap.
- Economy: price table and hire costs from the spec; bot gets `frictionIndex` (share of customers who waited > 6 s, per phase), `affordableAtClosing`, `daysToComplete`; targets: day-1 income ≈ 250, day 3 ≈ 600, day 5 ≈ 1 100, day 8 ≈ 2 000; affordable options at closing 2–3; area 1 complete in 10–12 days; friction 30–60 % in rush, < 20 % outside; lost sales 5–12 %/day. Tune within: prices ±40 %, zone costs ±40 %, phase spawn mults ±25 %.
- Strip: a 4-minute day strip (`--day`) showing morning, rush banner, closing card.

Commit `feat: day rhythm, weekends and holidays, goals, station stars, scarcity economy`.
